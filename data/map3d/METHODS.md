# MAP3D methods and integration notes

All acquisition and processing ran as one agent with Python 3.11 standard-library modules. Nothing was installed. Retained changes are under this directory; source downloads and redundant outputs were hashed before cleanup. `discarded_downloads.json` records discarded intermediates. `http_evidence.json` preserves surviving response metadata, including failed requests; `download_accounting.json` explains its conservative transfer bound.

**Buildings.** `building_stats.json` separates source counts from recommended cartographic extracts. OSM's AOI count query returns four counts: all building-tagged nodes/ways/relations, height-tag presence, levels-tag presence, and both. A tag is not a surveyed value. Zone geometry counts exclude open ways and relation member duplicates. Multipolygon members are joined; inner rings are assigned to containing outer rings. `geometry_checks` lists skipped chains/features. Approximate rectangles are in `sources.json`; they are not official neighbourhood boundaries.

Two Microsoft zoom-9 partitions were selected from the published CSV using quadkey intersection. AOI boundary footprints were clipped, yielding 909,695 features; no positive height was found. Core polygons were clipped to the five rectangles. Values of -1, missing values and nonpositive heights never become invented building heights.

The Google 2023 manifest is public and explicitly covers Brazil. GeoTIFF storage pixels are 0.5 m, but effective product resolution is about 4 m. Seven overlapping COGs supplied core-zone samples. `google_height_sources.json` and `google_height_sources_osm.json` retain exact COG URLs, band definitions, TIFF tags and sample/block counts. TIFFs are planar float32, DEFLATE, floating-point Predictor 3. The decoder restores byte-plane differences and endian byte order without GDAL. Public indexes and only relevant compressed height-band blocks were fetched with HTTP Range. Blocks were discarded after extracting heights.

Some S2 tiles have rectangular bounding boxes containing large no-data areas outside the valid S2 footprint. A single bounding-box selection would have left artificial holes: sampling all covering candidates and retaining valid positive samples resolves most of them. Heights use the centre of the *clipped geometry bounding box*, which is reproducible but can lie outside a concave footprint, in a courtyard, or on a neighbouring roof. There is no independent roof-height accuracy validation. Original explicit OSM heights are preferred; otherwise Google height estimates replace the levels-based assumption; a remaining levels tag uses 3 m/storey and is labelled inferred. Heights of zero, -99, nonfinite values and values >=900 m are rejected.

Recommended geometry prefers OSM footprints, then adds Microsoft polygons that do not intersect OSM polygon interiors. This is conservative cartographic conflation, not a cadastral union or a verified count of physical structures. It can discard valid overlapping neighbours. Each final feature carries `height_m`, `height_source`, `footprint_source` and a stable source ID. OSM raw tags, names and Microsoft confidence are retained where available. `height_raster` maps Google assignments to COG metadata keys. Zone counts overlap and must not be summed as globally unique IDs. Current OSM/Microsoft footprints and retrospectively released datasets are not contemporaneous May 2024 observations.

**Terrain.** Four Skadi HGT.gz objects cover the AOI and the margins of complete terrain tiles: S30/S31 W052/W051. Each decompresses to 3601² big-endian signed int16 values. `dem/terrain.json` describes the clipped 1153 × 2269 grid; `terrain.i16.zlib` stores little-endian int16 metres with -32768 no-data. One arc second is roughly 27 × 31 m here; source accuracy is not sub-metre. Skadi merges source terrain; Brazil is primarily SRTM with GMTED/ETOPO fill. Pixel-level source lineage was not independently audited. The source is a surface model with urban/canopy bias, not a validated bare-earth model.

`terrain-rgb/` contains complete AOI-intersecting XYZ tiles at z9–14, 256² pixels. Height = -10000 + (R × 65536 + G × 256 + B) × 0.1 metres. Source bilinear samples were quantized to 1 m to match integer source precision. PNGs use ordinary RGB or a lossless per-tile RGB palette after that quantization; browser image decoding recovers the correct RGB bytes. Oversampling at z14 adds no terrain detail. `terrain_stats.json` records palette counts and sizes; tests validate every PNG CRC/decompressed row and selected height roundtrips (maximum tolerance 0.55 m versus the unquantized grid interpolation). No source pixels were missing across full tile margins. After cleanup the DEM reader can sample the retained cropped grid; regenerating complete tile margins requires reacquiring the four HGT files.

ANADEM's 22J object is tiled float32, DEFLATE, predictor 1, and supports 206 ranges. Its full 1.58 GB file was not downloaded. MIT in the source repository is not treated as proof of an unrestricted data grant. GLO-30 is a DSM; FABDEM removes forest/building biases but imposes noncommercial/share-alike conditions. The municipal 2010 1 m ImageServer is reachable, but its licence/datum metadata are blank. None of these alternatives was silently substituted into the ground model.

**Water.** Existing depth zlib streams were decoded as little-endian uint16 centimetres, 65535 no-data. Every fifth depth cell, offset two pixels from the upper-left raster corner, supplies a sample at the centre of a 100 m sampling cell. This is a 20 m depth lookup at 100 m spacing, not an area average. UTM22S inversion and forward checks have maximum error in `water_sanity.json`. All core-zone centres are present, including null depth cells. DEM heights are bilinear, and surface is added before final centimetre rounding. Overlapping zones share one sample with multiple zone names.

SRTM is nominally EGM96 orthometric; Copernicus/FABDEM are EGM2008, ANADEM inheritance is not independently proven, and municipal/gauge datums require documentation. A relative depth alone cannot resolve these references. Cross-source terrain differences, urban roof bias and 2000 versus 2024 terrain changes can create implausible absolute water surfaces. The samples are diagnostic approximations, not an observed water-level layer or routing/safety guidance. Airport's 2.56 m agrees approximately with the brief; Mercado is no-data, not 0 or 1.5 m. The computed 51.46 m maximum is evidence of mismatch, not a flood crest to display as validated. Geoid/local-datum corrections are required before combining these heights with geocentric/ellipsoidal 3D Tiles.

The inherited EMS depth metadata contains conditionsUnknown and an INSPIRE Article13_1a restriction identifier. Public CEMS citation guidance provides open reuse subject to exceptions. This conflict is retained explicitly; public redistribution of depth-derived samples needs clarification. The existing depth files were supplied by the workspace and were not redownloaded or modified.

**Basemap/offline use.** Protomaps 20261024 v4.15.2 was extracted from a PMTiles v3 archive using header, root, leaf and grouped payload HTTP ranges. Internal directories and vector tiles are gzip. Hilbert IDs select intersecting XYZ tiles, with TMS Y inversion only when writing SQLite MBTiles. Exactly 2,716 requested tiles are present, none missing; size per zoom is in `basemap_stats.json`. Individual tiles retain context outside the AOI, especially at low zoom: this is a tile-pyramid extract, not a geometry-level clip.

`serve_offline.py` serves this folder and reads MBTiles without additional libraries. The dynamic `/style.json` localizes all data/glyph/sprite URLs. Complete building files are stored as gzip GeoJSON; `/buildings/recommended_<zone>.geojson` sends their compressed bytes with the correct Content-Encoding and application/geo+json type. The 471-feature `buildings/core_samples.geojson` is an ordinary review sample. It is not a replacement for complete zone data. The style's glyphs cover Latin/Portuguese (0–511) for Noto Sans Regular/Medium/Italic; other scripts require additional ranges. Both sprite pixel densities and licence notices are bundled.

The shipped MBTiles path needs no PMTiles JS. Switching formats requires the PMTiles JS protocol and HTTP Range serving; Python's basic SimpleHTTPRequestHandler does not provide that protocol or a suitable PMTiles Range implementation. Fetched current protocol metadata identifies BSD-3-Clause, correcting the brief's MIT assumption. No WebGL application or MapLibre/deck.gl runtime bundle was created; vendor the workstation's JS/CSS and wire in these data sources before claiming application-level offline readiness. The completed smoke test is for local data serving, not a browser-rendering test.

**Reproduction and checks.** No commands in `remaining_tools.json` were executed. For offline verification run `python out/MAP3D/self_check.py`. It parses JSON and gzip GeoJSON, checks clipped coordinates and height fields, SQLite/gzip streams, PNG CRC/encoding, water arithmetic and local HTTP asset routes. Re-run manifest generation after any data change. Do not run acquisition scripts casually: they redownload sources and can temporarily exceed the retained payload budget. Online reproduction requires sequential acquisition (`probe.py`, `probe2.py` through `probe6.py` as needed, `acquire.py`, `terrain_extra.py`, `acquire_basemap.py`, `google_local.py`, `acquire_osm.py`/`osm_canoas.py`), followed by the documented building/terrain/water processors. The scripts and hashes capture this run; external URLs/releases may expire. Per-process request logs were added after early probes to prevent shared-log overwrites, and the final accounting retains an explicit reserve rather than pretending to have an exact wire-byte total.
